## Findings

### CR-20261017-01 — P1: unmeasured mutants counted as graded

At the reviewed revision, `applyDevScore` in
[`internal/advpool/driver.go`](../../internal/advpool/driver.go) reconstructed
the graded count from generated mutants minus invalid mutants. It omitted the
scorer's separate unmeasured category: mutants whose selected command failed
on compliant code or did not reach the audited file.

The counterexample supplied eight distinct mutants. One executed and was
killed; seven received commands that failed the compliant-code probe. The
scorer reported one graded kill and seven unmeasured mutants. The driver
reported eight graded, no survivors, and `certified`, logging
`killed 8 of 8 graded mutants`. The interval and stored total therefore
described an exam that had not run.

Expected: only measured outcomes contribute to the graded denominator and
exam-size check; unmeasured outcomes remain separately disclosed.

Resolution: fixed in `7bb55197` (#437). The 2026-10-18 rerun reported one
graded, seven unmeasured and `needs-review`. Regression coverage is in
[`exam_evidence_test.go`](../../internal/advpool/exam_evidence_test.go).

### CR-20261017-02 — P1: duplicate edits inflated the certification sample

The scorer deliberately graded one representative of byte-identical edits
and attributed its outcome to every copy. The interval in
[`internal/advpool/aggregate.go`](../../internal/advpool/aggregate.go) also
used the copied count as its sample size.

The counterexample supplied eight copies of one fault. One unique edit ran;
eight were recorded killed, seven duplicates were disclosed, and the verdict
was `certified` with `ExamIndicative=false`. Repeating a measurement had
bypassed the minimum-evidence rule.

Expected: use distinct measured edits for the certification interval. Keep
the deliberate output weighting separate from the number of observations.

Resolution: fixed in `7bb55197` (#437). The 2026-10-18 rerun treated the
sample as one distinct edit and returned `needs-review`. Regression coverage
is in [`exam_evidence_test.go`](../../internal/advpool/exam_evidence_test.go).
This closure concerns the certification decision checked in this review.

### CR-20261017-03 — P2: API review saw different bytes from its recorded commit

[`cmd/corral/review.go`](../../cmd/corral/review.go) created a detached
worktree at the recorded commit, but loaded the API prompt's scope from the
operator's checkout. Reproductions ran against the committed snapshot. An API
verifier could receive the same inconsistent scope.

The counterexample committed `return a - b`, then changed the checkout to
`return a + b` without committing. The API prompt named HEAD but showed
addition; its reproduction ran against subtraction and the finding was
demoted. This could invalidate findings because review and execution had
different inputs.

Expected: scope contents, reviewer and verifier prompts, and reproductions
refer to the same committed snapshot, excluding modified and untracked inputs.

Resolution: fixed in `d27e5ffd` (#438). The 2026-10-18 rerun showed the
committed source to the API reviewer. Regression coverage is in
[`review_snapshot_test.go`](../../cmd/corral/review_snapshot_test.go).

### CR-20261017-04 — P2: workspace reproductions contaminated later scripts

The opt-in workspace substrate reused one detached worktree for all
reproductions. A script could create or edit files, and later findings or
verifier scripts would observe that state. The runner restored its own
applied overlays, not arbitrary changes made by a script. The default jail
already provided fresh workspaces.

The first counterexample script replaced the source. A second script looked
for the replacement and exited zero; run alone on a fresh worktree at the
same commit, that identical second script exited one.

Expected: each finding and refutation executes from its own clean snapshot
of the recorded commit.

Resolution: fixed in `dccd2be2` (#440). The 2026-10-18 rerun no longer
reproduced contamination. Regression coverage, including stray-file cleanup,
is in [`review_fresh_tree_test.go`](../../cmd/corral/review_fresh_tree_test.go).

## Recommendations recorded at the time

- Carry mutant identity, disposition and diagnostic together, deriving
  counts from measured outcomes. Check consistency across scorer, converged
  and timeout verdicts, records and attestations.
- Preserve the skip census and explicitly distinguish essential execution
  checks from optional runtime checks. A green aggregate suite does not prove
  skipped paths ran.
- Consider a zero-model baseline readiness check using the audit's actual
  seed, dependency binds and test command before paid seats run.

These are recommendations from this round, not additional reproduced defects
or a claim about their implementation status today.
