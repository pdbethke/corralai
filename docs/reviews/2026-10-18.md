## Findings

### CR-20261018-01 — P2: stored evidence omitted a known interference failure

Location at the reviewed revision: the evidence rendering in
[`cmd/corral/scans.go`](../../cmd/corral/scans.go), with the conversion in
[`certify_repo_record.go`](../../cmd/corral/certify_repo_record.go).

The new together check recorded whether authored tests that passed alone
failed as a combined file against unmutated code. The live report warned on
failure. The stored full verdict retained that result, but the later evidence
reader printed only the killed IDs and authored source.

Executed counterexample: pass a verdict with `AuthoredTogether="fail"`,
failure output and two proven IDs through the real `buildScanFileRows`
conversion, then through the real `runScans` command using its fake-reader
seam. The JSON retained the failure. The evidence output showed
`killed: m1,m2` and the combined source, without the interference warning or
failure output. The same result passed to the live renderer printed both.

Impact: a person retrieving evidence later could adopt a combined test file
already known to fail. The individual proofs remained valid; the defect was
the reader dropping a material qualification, not corruption of the raw
stored verdict.

Expected: the evidence reader carries the together result and failure output
beside the authored tests, preserving the distinction between passed and not
checked.

**Resolution checked 2026-10-19:** fixed in `c402830d`, merged in #446. The
reader now extracts the together outcome from stored verdict JSON. The same
qualification also reaches the brief's text and JSON output. The focused
checks below passed at `7fefffc0`:

- `TestScansShowEvidence_CarriesTheTogetherOutcome`, including fail, pass
  and not-checked cases, through the converter and reader.
- `TestBriefCarriesTheTogetherFailure`, including text and JSON output.

Regression sources:
[`scans_evidence_test.go`](../../cmd/corral/scans_evidence_test.go) and
[`brief_test.go`](../../cmd/corral/brief_test.go).

### CR-20261018-02 — P2: aliased JavaScript imports produced a partial critic list

Location at the reviewed revision: `jsNamesOnly` and the fixed callee-name
lookup in [`js_testnames.go`](../../internal/lang/js_testnames.go).

Executed fixture:

```javascript
import { test, test as check } from 'node:test';
check('hidden', () => {});
test('visible', () => {});
```

The real Node v22.23.3 test runner executed both `hidden` and `visible`.
The source scanner returned only `["visible"]`, rather than declining to
supply a complete list. A fake-model reply judging only `visible` was
accepted by the actual typed-critic parser with this summary and no
incomplete marker:

```text
typed critic judged 1 test(s), 0 flagged
```

The scanner treated the imported identifier as merely named, then never
followed the alias. Its handling of passed-around functions and node subtests
did not cover this import form.

Impact: advisory critic coverage could be incomplete while recorded as
complete. The critic did not gate certification.

Expected: track aliases exactly, or decline to provide a static list when
unresolved aliases prevent enumeration of every test.

**Resolution checked 2026-10-19:** fixed in `4e9470d8`, merged in #446. The
scanner returns no list for unresolved renamed test or suite functions,
including the exact fixture above. It also handles renamed default and
required node test bindings conservatively.
`TestJSTestNamesInSourceFailsClosed` passed at `7fefffc0`, including the
original import-alias case. Regression source:
[`js_testnames_test.go`](../../internal/lang/js_testnames_test.go).
