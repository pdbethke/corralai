## By runner

A language has a runner capability when any of its runners does; this is which. corral recognises the runner from the test command you pass, or from the package script it runs: `composer` reads `composer.json` and hands the runner its arguments after `--`; `npm` reads `package.json` and hands the runner its arguments after `--`; `pnpm` reads `package.json` and hands the runner its arguments after `--`; `yarn` reads `package.json` and hands the runner its arguments directly. A script gets the runner's arguments only when it is one command, since a launcher appends them to the end of the script. `--runner <id>` names the runner when corral cannot read it. A command whose runner corral does not know (a `make` target) is graded exactly the same, by exit code, as its language's default runner, except that it never gets a fail-fast flag or report flags. Report flags are added to every run corral grades with, so the project's own setting of the same option (pytest's `-r`) cannot hide the lines corral reads the failing test from; an option that turns the summary off altogether still hides those lines. A runner with a failure hook records its failing tests itself, in a run corral wraps to load the hook, and corral reads that record first: no report setting hides it, and the printed lines are read only where the record is missing or cut short, or the command is one corral cannot rewrite either (see the runner's note). The scan line says so when either is added.
